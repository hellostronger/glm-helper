# 方案背景 · 为什么这么设计

> 给想了解原理的人看；只想安装看根目录 `README.md` 和 `INSTALL.md` 即可。

## 问题与根因

社区反馈 glm5.4 两个问题：**雷霆思考**（思考过长、循环验证、反复推演未确认分支）与 **token 使用率低**。

根因共识：**单纯告诉模型"少思考"几乎无效，有效的是结构性限制**——把思考限制在特定节点 + 把执行外包给快模型。雷霆思考的三种典型形态：

1. **无终止的验证循环**——测试绿了继续验证第二遍第三遍；
2. **思维链推演未确认分支**——需求有 ≥2 种解释时，脑内把每个分支的实现细节都设计一遍，最后只用一个；
3. **重复测量 / 无消费者的侦察**——盘上已有读数还跑新一轮；"随便看看"没有用途。

这些 token 没有对应产出，就是使用率低的原因。

## 四层方案（由浅入深，全部独立可用）

```
L1 · Discuss Before Diverging   —— 开工前：分叉先对齐（必装，所有场景）
L2 · Progress Over Polish       —— 开工后：主任务锚定（单模型场景加装）
L3 · 模型分工（精简版/完整版）   —— 结构性省算力（贵模型只管想，便宜模型干活）
L4 · Token 经济学               —— 成本总账：缓存命中 × 调用次数 × 单价（随时可贴）
```

- **L1**（`rules/discuss-before-diverging.md`）：需求有 ≥2 种合理解释时硬熔断——思维链不推演未确认分支、对齐前侦察 ≤3 文件、单轮给 2–4 选项对齐。
- **L2**（`rules/progress-over-polish.md`）：开工建台账（3–5 条可验证完成标准）、动作标注、细节预算两层（阻塞才放宽 + 滚动释放，单子问题 ≤20 次调用硬熔断）、主路径跑通前禁写测试。
- **L3**：**贵的想，便宜的做**。精简版 `zcode-worker/`（一条 AGENTS.md + 10 行 worker，逐任务 review）；完整版 `leader-coder/`（Leader 技能 + 重装 coder，带 ROI 闸门、骨架先行、收口终审等重型纪律）。对比见 `zcode-worker/README.md` 末节。
- **L4**（`token-economics.md`）：缓存输入 ≈ 输出单价的 1/15，最贵的是缓存失效后的冷读。三板斧：万事子 agent（主上下文保持缓存命中）+ 单次调用批量读写（成本 = 上下文 × 调用次数）+ 上下文锁 256k。

总账公式：`总成本 ≈ 上下文 × 调用次数 × 单价`——L1/L2 砍无效思考量，L3 换单价，L4 砍乘数。

## 为什么有效（对照根因）

| 根因 | 对策 |
|---|---|
| 无终止的验证循环 | L3"通过即终止"+ L2 台账锚定；同错误三振即停 |
| 思维链推演未确认分支 | L1 硬熔断：每分叉 1 句话，实现细节只属于对齐后的单一路径 |
| 重复测量、无消费者侦察 | L3 ROI 闸门：先盘现成数据、输出必须有具名消费者、探针带硬时限 |
| 小模型被派大活 / 大模型干小活 | L3 分工：设计归 5.4，施工归 Flash，派单带落点与验收 |
| 缓存冷读、调用次数过多 | L4：万事子 agent、批量读写、上下文锁 256k |

## 每日传播口径（一分钟版）

- glm5.4 雷霆思考、token 使用率低，不是让它"少想"能解决的——要上**结构性约束**。
- 四层递进：① AGENTS.md 写"分叉前先对齐"；② 加"主任务锚定"；③ 贵模型只管想，便宜模型（Flash）干活；④ 记住总账公式 `总成本 ≈ 上下文 × 调用次数 × 单价`——缓存输入只有输出单价的 1/15，万事子 agent、批量读写、上下文锁 256k，输出占比就能抬到 3–5%。
