# ZCode 主模型 + worker 分工 · 精简版安装

> 这是模型分工（L3）的**精简版**：一条 137 行的 `AGENTS.md`（规则一+二+三，英文）+ 一个 10 行的 `worker.md` 子智能体。相比 [`../leader-coder/`](../leader-coder/) 的完整版 Leader 技能，它没有 ROI 闸门、骨架先行、收口终审等重型纪律，但安装最简单、上手最快。

## 文件

- [`AGENTS.md`](AGENTS.md) — 全局规则：规则一（分叉前先对齐）+ 规则二（主任务锚定）+ 规则三（模型分工）。主模型在会话开始时注入，worker **不读它**（`injectAgentsMd: false`）。
- [`worker.md`](worker.md) — 极简执行体定义：只完成任务书上的事，按验收标准自测，不扩范围不顺手重构。

## 安装（ZCode）

1. 用户级（对所有项目生效）：`~/.zcode/AGENTS.md`、`~/.zcode/agents/worker.md`。
   项目级：`<项目>/AGENTS.md`、`<项目>/.zcode/agents/worker.md`。
2. **必改一处**：`worker.md` 的 `model`。模型 ID 与套餐绑定（格式 `providerId/modelId`），让 ZCode 主模型列出你可用的模型 ID，原样填入。
3. 生效：新建会话，或当前会话发 `/reload`。
4. 验证：输入框打 `@` 能看到 `worker`；再派一个几行的小任务，返回即链路通。

## 规则三要点（分工怎么走）

- 主模型负责：对齐、分析、拆任务、派活、review；不亲手写代码、跑命令。
- 任务书四样给全：**目标、涉及文件、验收标准、禁止事项**。
- worker 返回后主模型**必须亲自读改动**再 review（不能只看汇报）；验证命令写进任务书由 worker 跑并回传原始输出。
- **可派发的唯一判据**：能写出一句可验证的完成标准并列出涉及文件就可交；写不出说明还在决策阶段，留给主模型。
- **兜底**：worker 未加载/被停用，或再派一次仍不合格 → 主模型自己干。

## 已知取舍

| 取舍 | 原因 |
|---|---|
| 命令结果只有一个来源 | 主模型 review 时不跑命令，结果都由 worker 回传 |
| 小任务不划算 | 几行的活，写任务书 + review 的开销比活本身大 |
| 任务书质量决定结果 | worker 严格照任务书执行，前提错了它就按错的前提做 |
| 长链工作移出主模型 | "写、跑、看、改"最长的链条由 worker 跑，主模型长链能力只在兜底时用 |

## 与完整版（leader-coder）怎么选

| | 精简版（本目录） | 完整版（leader-coder） |
|---|---|---|
| 安装成本 | 2 个文件，10 分钟 | 技能 + 子智能体 + 项目模板替换 |
| 执行体 | worker：10 行提示词，严格照任务书 | coder：自带安全规矩、测试配方、自证表 |
| 审查 | 逐任务 review | 不走查，收口批量终审 |
| 重型纪律 | 无 | ROI 闸门、骨架先行、探针时限、投入上限 |
| 适合 | 个人 / 上手 / 中小任务 | 团队长任务、算力敏感、真实数据风险高 |
